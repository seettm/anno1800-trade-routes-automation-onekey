# Trade Routes Automation — One-Key Edition

《纪元 1800》(Anno 1800) 贸易航线自动化 mod，**一键操控版**。

基于 [kr3v 的 Trade Routes Automation](https://github.com/kr3v/anno1800-trade-routes-automation) 改造而来，
把原本"必须手动建一条名字叫 `TRA_OW` 的贸易航线、再把船塞进去"的流程，
简化成 **选船 → 按一下快捷键 → 剩下的交给调度器**。

> 当前版本：**v1.9.7**
> 适用：Anno 1800 + 全部 DLC（旧世界 OW / 新世界 NW）

---

## 它做什么

1. **扫描区域**：把当前区域所有岛屿、水域采样点建成一张网格缓存。
2. **读真实库存**：直接走引擎接口读每座岛每种货的现有量与仓容量。
3. **算供需**：按货物类型分两套水位（见下节）。
4. **派船**：挑一艘空闲的被接管船，开去装货、返航卸货。
5. **循环**：卸完自动接下一单，全程无人值守。

整个过程的状态**印在船名上**（这游戏没有任何 Lua 屏幕提示接口，实测 5 条候选全部失败）。

## 调度阈值（v1.11.2 起）

原版所有环节都用一个硬编码的 **50** 当最小发运量，结果一座岛饿着、另一座岛还剩 30 吨，
调度器会判定"没有任何岛屿可供"，船一动不动。现在按货物类型分开：

| 货物类型 | 判定方式 | 最小发运量 |
|---|---|---|
| **生活必需品**（居民消耗品） | 双水位：低于容量的 **60%** 就补货；高于容量的 **30%** 就出货 | **10** |
| 其它（工业原料、建材） | 与目标量的差值 | 50（原版行为） |

"生活必需品"没有写死 GUID，而是直接读 `residence_info.json` 里各级住宅的消耗列表 ——
新 DLC、新人口等级只要被扫描到就自动纳入。

**判定粒度是"每座岛"**（v1.11.1）：只有该岛真的住着会消耗这种货的人口等级，它才算必需品。
农业岛不会把小提琴、蒸汽马车当必需品；纯生产岛没有居民数据时退回全区并集兜底。
启动后 `base.log` 里会打一段 `[TRAtUI] 岛 xxx：必需品 N 种 —— 鱼, 面包, 啤酒…`，
可以直接和游戏里的需求面板逐项对照。

### 实时需求（v1.11.2）

居民需求表是用 `GetMaxHappiness/Money/SupplyForGood` 探出来的，会把**加工链原料**
也列进去（农民那一行会出现 Flour）。可原料没人加工就是废料 —— 岛上没面包厂，
送面粉过去只会堆仓库。

所以现在：**凡是本区域自有工厂消耗的原料，都从居民需求里摘掉，改由「岛上有那座厂」决定**。
判定数据来自 `Region_ProductionGUIDs`（你真正建了哪些厂），不是静态表：

| 岛上的情况 | 结果 |
|---|---|
| 没有面包厂 | 不要面粉（居民需求里的 Flour 被剔除） |
| 建了面包厂 | 立刻要面粉（来自面包厂的原料需求） |
| 没有捕鱼厂、有农民 | 照常运鱼（鱼是居民终端消费品，不属于加工原料） |

`Bar: X` / `Restaurant: X` / `Chemical Plant: Shampoo` 这类**消费场所**不算加工厂，
否则酒吧会把杜松子酒、洗发剂厂会把肥皂从居民需求里摘掉而导致该运的不运。

### 空区域自动跳过（v1.11.2）

没解锁/从没进去过的区域（例如没开新世界）不再每 2 秒刷一次「等待扫描」：
区域既不是当前地图、又没有历史缓存时直接静默停泊，进入该区域后自动接上；
缓存建好但既无我方岛屿又无我方船只的区域，直接跳过整条调度循环。

想调松紧不用改代码，改 `data/trat_fork/mod_trade_planner_ll.lua` 顶部的 `Policy`：

```lua
TradePlannerLL.Policy = {
    minTransferNormal = 50,    -- 非必需品最小发运量
    minTransferBasic  = 10,    -- 必需品最小发运量（调小=更积极，改 50=退回原版）
    basicTargetRatio  = 0.6,   -- 低于容量的这个比例就补货
    basicKeepRatio    = 0.3,   -- 高于这个比例的部分才会外运
    basicNeedEnabled  = true,  -- false = 全部按 50 处理
    basicNeedScope    = "island", -- "island"=按岛实际人口 | "region"=全区并集(v1.11.0 行为)
    realtimeDemand    = true,     -- 加工链原料（面粉等）只在岛上有对应工厂时才运
    extraBasicGoods   = {},    -- 手工追加算作必需品的 GUID，如 {120008} 木材
};
```

## 安装

1. 解压到：
   ```
   C:\Users\<用户名>\Documents\Anno 1800\mods\
   ```
   确保路径形如 `...\mods\TradeRoutesAutomation_OneKey\modinfo.json`。

   > ⚠️ **必须放 `Documents\Anno 1800\mods\`**。
   > 新版内置加载器不扫描游戏根目录的 `mods\`，放错位置会导致"装了什么都没发生"。

2. 启动游戏 → 读取存档 → 弹出「模块」窗口时**给本 mod 打勾**（本地 mod 默认是「未启用」）。
3. 进存档，选中一艘船，按 `Shift + O`。

## 搬运舰队航线（数量不限，v1.12.3）

> **先说清楚**：游戏没有开放"用脚本创建航线"的接口（原版作者 kr3v 也是让玩家手工建一条
> `TRA_OW` 假航线再挂船），所以本 mod **不能**在你的航线列表里凭空生成航线。
> 但"用航线管理搬运舰队"这件事可以全自动 —— 航线只需要你手工建一次。

**要建几条就建几条**，命名规则是 `TRA_<区域>_<标签>`：

| 区域 | 名称示例 |
|---|---|
| 旧世界 | `TRA_OW_A`、`TRA_OW_B`、`TRA_OW_C` … `TRA_OW_Z`、`TRA_OW_01`、`TRA_OW_FOOD` |
| 新世界 | `TRA_NW_A`、`TRA_NW_B`、`TRA_NW_01` … |

标签规则：

- 1～4 位**字母或数字**，前面可带一个分隔符 `_`、`-` 或空格，大小写不敏感
- `TRA_OW_A` / `TRA_OW-A` / `TRA_OW A` 三种写法等价
- 标签超长或含中文/下划线（如 `TRA_OW_运输队`、`TRA_OW_A_B`）→ 仍会被纳管，
  但记为"无后缀舰队"，**不参与分组统计**
- 既不是 `TRA_<区域>` 开头（如 `我的运输线`）→ 完全不纳管

> 游戏里航线列表本身没有硬性数量上限，几十条都能建；真正的限制是你的屏幕能看清几行。

然后把想交给自动化管的船**拖进这些航线**即可，不需要再按 `Shift+O`：

| 你在游戏里的动作 | mod 的反应 |
|---|---|
| 把船拖进 `TRA_OW_A` | 下一轮调度（约 10 秒）自动纳管 |
| 把船从航线拖出 | 自动释放，不再接单 |
| 按 `Shift+O` 手动接管 | 记为"手动"，拖出航线也不会被释放 |

船名会带上舰队分布，按标签字母序排列，最多列 4 组（多出来的用 `+N`）：

```
TRA_运行_4艘_A2B2_面粉63
TRA_运行_5艘_A2C1E2_木材50      ← 三个舰队
TRA_运行_8艘_A1B1C1D1+2_平衡    ← 六个舰队，只列前四个
```

按 `Shift+K` 会列出全部舰队：
`舰队 A=2艘 B=2艘 C=1艘 无后缀=0艘｜手动接管=0艘`

兼容原版写法：一条不带后缀的 `TRA_OW` 同样会被接管（记为"无后缀舰队"），
可以和 `TRA_OW_A` / `TRA_OW_B` 等同时存在。

### 航线纳管 vs 手动接管：等价吗？

**调度内核完全等价** —— 两种方式最终都写进同一份接管清单，走同一套派单、
同一套船名看板、同一套阈值判定。差别只在「怎么进来 / 怎么出去」：

| 维度 | 航线纳管（`TRA_OW_A`） | 手动接管（`Shift+O`） |
|---|---|---|
| 生效方式 | 把船拖进航线，约 10 秒自动纳管 | 选中船按 `Shift+O`，需船已停稳 |
| 批量 | 可以一次拖一批 | 一次一艘 |
| 退出自动化 | 把船拖出航线，自动释放 | 只能 `Shift+I` 全部释放 |
| 与游戏航线 AI | **有冲突**：船在航线上，有 ≥2 站点就会被 AI 拉着跑 | 无冲突，船不在任何航线 |
| 清单丢失后 | 仍会被识别（靠 `TRA_<区域>` 航线名兜底） | 完全不认 |
| 释放后船名 | 还原为玩家原名（v1.12.2 起） | 还原为玩家原名 |

一句话选择：

- **只想让它稳定搬货** → 手动 `Shift+O` 最干净，没有航线 AI 抢船的问题
- **船多、想分组管理** → 用航线，但每条航线**只能留一个待命站点**（或直接暂停航线）

**两条舰队要不要分工？** 不需要。调度是「每艘船只接一单、按距离最优分配」，
两条航线的船天然会分摊不同订单，不会抢同一批货。两条航线的意义是**分组管理**
（比如 A 跑近岛、B 跑远岛），不是调度规则。

**航线名打错了怎么办？** 不影响游戏，但不会被纳管。日志里会有一行：

```
[TRAtUI] 检测到航线：TRA_OW-A —— 只有 TRA_OW / TRA_OW_A / TRA_OW_B 会被纳管
```

照着改名字即可。

**船挂进航线后反而不动了？** 这是这套机制唯一必须手工处理的坑：
游戏自带的航线 AI 会按航线里的站点自己开船，和本 mod 的派单互相打架。
日志里表现为「船连续多轮空舱移动」——本 mod 派单时舱里一定有货，空舱移动就是别的系统在开。

处理办法（二选一）：

1. **每条航线只留一个站点**，且这个站点选你希望船待命的那座岛。船待命时不动，
   被派出去卸完货会自己开回来，冲突最小。
2. **在航线界面把这条航线暂停**。暂停后航线 AI 不再派任务，船完全交给本 mod。

按 `Shift+K` 会直接报「注意 有 N 艘船在空舱移动」，不用去翻日志。

## 快捷键

| 按键 | 功能 | 屏幕反馈 |
|---|---|---|
| `Shift + O` | 接管当前选中的船 | 船名变成 `TRA_...` |
| `Shift + P` | 扫描当前区域（已有缓存会跳过） | 画面自动抖动、镜头移动 |
| `Shift + F` | 强制重扫（忽略缓存） | 同上 |
| `Shift + K` | 状态自检 + 必要时就地复活调度器 | 船名刷新 |
| `Shift + U` | 开 / 关自动化 | 前缀 `TRA_` ↔ `TRA-OFF_` |
| `Shift + I` | 释放所有被接管的船 | 船名还原 |

`Ctrl + 同字母` 为备用键（部分输入法/键位下 `Shift+字母` 不送达时可用）。

## 船名看板

所有被接管的船会显示同一行状态，每 10 秒自动刷新：

```
TRA_运行_3艘_Wood200
```

| 片段 | 含义 |
|---|---|
| `运行` | 调度正常 |
| `待扫描` | 区域网格为空，按 `Shift + P` |
| `已停止` | 调度协程不在了，按 `Shift + K` 尝试复活 |
| `卡住` | 协程还在但 90 秒无心跳，多半在等船靠岸 |
| `已关闭` | 按过 `Shift + U` |
| `3艘` | 已接管的船数 |
| `Wood200` | 当前最大缺口（货物 + 数量）；`平衡` 表示无需调货 |
| `A2B2` | 舰队分布（用航线时才出现）：A 舰队 2 艘、B 舰队 2 艘；最多列 4 组，`+2` 表示还有 2 个舰队没显示 |

完整需求清单（每种货物缺多少、缺在哪座岛）另写在：

```
C:\Users\<用户名>\Documents\Anno 1800\log\TRAtUI_status.txt
```

## 常见问题

**船不动 / 不搬运，怎么快速定位？**

按 `Shift+K`，按下面的顺序看：

| 提示 | 含义 | 怎么办 |
|---|---|---|
| `调度器=已停止` | 调度协程没了 | 按 `Shift+K` 会自动尝试复活，不行就重启游戏 |
| `待扫描` / `地图岛屿=0` | 区域没有网格数据 | `Shift+P` 扫描当前区域 |
| `有 N 艘船在空舱移动` | 航线 AI 抢走了船 | 航线只留一个待命站点，或暂停航线 |
| `需求：暂无数据` | 还没跑完一轮 | 等 10 秒再看 |
| 缺口全是「没有任何岛屿可供」 | **两座岛都没这种货** | 不是调度问题：去开岛或补产能 |

最后一条是最常见的误判 —— 调度器已经把能搬的都搬完了，
剩下的缺口在全区都找不到货源，加船也不会动。

---

**按了快捷键毫无反应**
先确认 mod 在游戏内模块列表里是**已勾选**状态。本地 mod 出现在列表里 ≠ 生效。

**船一动不动**
按顺序查：
1. `Shift + K` 看状态。显示 `待扫描` → 按 `Shift + P`。
2. 扫描时必须**人在该区域画面里**，不要停在世界地图总览。
3. 扫描会带动镜头跳动，属正常现象，别碰鼠标。
4. 切到窗口外游戏会暂停逻辑帧，船必然不动——**留在游戏画面里**。
5. 还是没有？看 `log\` 下的 `TrRAt_*_base.log` 与 `trade-execute-iteration.log`。

**扫描结束没看到任何提示**
这游戏不提供 Lua 提示接口。扫描完成的唯一迹象是 `base.log` 里出现
`扫描结束：新扫 N 座 / 跳过 M 座 / 失败 0 座`。

**`Production GUID 1900xxxxxx not found in AnnoInfo.FactoriesInfo`**
部分 DLC / 其他 mod 的工厂不在供给表内，属已知限制，不影响原版建筑。

## 打包（仅开发者需要）

```bash
python tools/build_release.py
# 产物默认在 mods 目录之外：<Anno 1800>\_build\TradeRoutesAutomation_OneKey_v<版本>.zip
```

> ⚠️ **绝对不要把 zip 放在 mod 目录里面**（比如 `mods\TradeRoutesAutomation_OneKey\dist\`）。
>
> 游戏内置加载器会**递归扫描** mods 目录，把 zip 当成第二个 mod 加载。日志里会多出一条：
>
> ```
> Load TradeRoutesAutomation_OneKey_v1.9.7 (unversioned) from ...\dist\...zip
> ```
>
> 后果：同一个 mod 加载两遍，两份相同 GUID 的 Trigger（1475200100）互相冲突，
> 主脚本 `_main.lua` 直接不执行 —— 所有热键 `require` 失败，表现就是"按了完全没反应"。
>
> 打包脚本已内置保护：输出目录落在 mod 目录内会直接拒绝并报错退出。
