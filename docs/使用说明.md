# TRAtUI 使用说明（v1.12.1）

> 一句话：**扫描一次区域 → 把船交进来 → 之后它自己算账、自己派船、自己卸货。**
>
> 适用：Anno 1800 + 全 DLC（旧世界 OW / 新世界 NW），单人游戏。

## 1. 这是什么

`TRAtUI` 是 [kr3v 的 Trade Routes Automation](https://github.com/kr3v/anno1800-trade-routes-automation) 的独立分支。

它解决的是同一件事：**同一个区域内，把货从富余的岛自动运到缺货的岛，不用你手画几十条贸易航线。**

每个区域（旧世界、新世界）各跑一条独立循环，互不干扰。**不做跨区域运输**。

与原版的关系：

| | 原版 | 这个分支 |
|---|---|---|
| 怎么把船交给它 | 必须手工建一条名字以 `TRA_` 开头的航线，再把船拖进去 | 两种都行：航线（见第 4 节）或选中船按 `Shift+O` |
| 状态在哪看 | 日志 | 直接印在船名上，每 10 秒刷新 |
| 最小发运量 | 全环节硬编码 50 | 必需品 10，其它 50 |
| 需求判定 | 居民需求表（含加工原料） | 加了「岛上有没有那座厂」的实时判定 |

**与原版互斥**：两个 mod 同时启用会抢同一批船，只能开一个。

## 2. 安装

1. 解压到：

   ```
   C:\Users\<用户名>\Documents\Anno 1800\mods\TradeRoutesAutomation_OneKey\
   ```

   正确结构是 `...\mods\TradeRoutesAutomation_OneKey\modinfo.json` 直接可见。

2. 启动游戏 → 读档 → 弹出「模块」窗口时**给本 mod 打勾**。

3. 进存档，按 `Shift+P` 扫描当前区域。

三个必踩的坑：

| 坑 | 现象 | 正确做法 |
|---|---|---|
| 放到游戏安装目录的 `mods\` | 装了等于没装，模块列表里根本没有 | 必须放 `Documents\Anno 1800\mods\`，新版加载器不扫游戏根目录 |
| 本地 mod 默认「未启用」 | 列表里能看到，但不生效 | 模块窗口里手动打勾 |
| 改完文件没重启游戏 | 以为改坏了 | Lua 只在进档时加载一次，改代码后必须完全退出游戏 |

## 3. 快速上手

### 第一步：扫描区域（`Shift + P`）

进到要自动化的区域（比如旧世界），按 `Shift + P`。

- 首次会先建区域网格：**画面剧烈跳动约 10 秒**，正常，别动鼠标、别切区域。
- 之后逐岛扫描，每座岛 20～40 秒，画面同样会跳。
- 结束提示：`扫描结束：新扫 N 座 / 跳过 N 座 / 失败 N 座。`

> 为什么画面会跳：引擎没有「读取世界坐标」的接口，只能把镜头瞬移到采样点读一次再瞬移回来。原 mod 的固有做法，绕不过去。
>
> 扫描会写磁盘缓存，**同一个档不用重复扫**。新占岛 / 新建厂之后要再扫一次。

### 第二步：把船交给它

两种方式，任选一种（详见第 4 节）：

- **省事**：建一条 `TRA_OW_A` 航线，把船拖进去。
- **最少配置**：点中一艘船，按 `Shift + O`。

### 第三步：什么都不用做

调度器每 10 秒左右跑一轮：统计各岛盈缺 → 找水路 → 派空闲船 → 装货开过去 → 卸货 → 接下一单。

随时按 `Shift + K` 看状态。

## 4. 交给它的两种方式

### 方式 A：航线舰队（推荐给多船）

游戏没有开放「用脚本创建航线」的接口，所以**航线要你手工建一次**，之后全自动。

在航线界面新建航线，名字必须一字不差：

| 区域 | 舰队 A | 舰队 B |
|---|---|---|
| 旧世界 | `TRA_OW_A` | `TRA_OW_B` |
| 新世界 | `TRA_NW_A` | `TRA_NW_B` |

然后把船拖进去，约 10 秒后自动纳管，**不用按任何热键**。

| 你的动作 | mod 的反应 |
|---|---|
| 把船拖进航线 | 自动纳管，开始接单 |
| 把船拖出航线 | 自动释放，不再接单 |
| `Shift+O` 手动接管 | 标记为「手动」，拖出航线也不会被释放 |

**关键：每条航线只留一个站点，选你希望船待命的岛。**

游戏自带的航线 AI 会按航线里的站点自己开船，和本 mod 的派单抢控制权。站点一多，船就一直被 AI 拉着跑，永远不停下来接单。这是「挂了航线反而不搬运」的唯一原因。

不想删站点也行：**在航线界面把这条航线暂停**，效果一样。

兼容原版写法：一条不带后缀的 `TRA_OW` 也能被接管，可以和 A/B 同时存在。

### 方式 B：手动接管（`Shift + O`）

1. 鼠标左键点一下那艘船（点船体，屏幕右下出现船的肖像/船名面板）。
2. 按 `Shift + O`。
3. 船名立刻变成 `TRA_运行_1艘_...` —— 这就是成功标志。

要求：

- 必须**单艘**船。框选多艘、点左侧船列表图标，都不算「选中」。
- 船要**已停稳**（不在航行中）。
- 货舱有货也能接管，调度器会先卸载再开始。

### 两种方式等价吗？

**调度层面完全等价**：两种方式最终都写进同一份接管清单，走同一套派单、同一套船名看板、同一套门槛判定。差别在「怎么进来、怎么出去、有没有外部干扰」：

| 维度 | 方式 A 航线舰队 | 方式 B 手动接管 |
|---|---|---|
| 生效方式 | 拖进航线，约 10 秒自动 | 选中船按 `Shift+O` |
| 批量 | 可以一次拖一批 | 一次一艘 |
| 退出自动化 | 拖出航线，自动释放 | 只能 `Shift+I` 全部释放 |
| 与游戏航线 AI | **有冲突**，靠"只留一个站点"规避 | 无冲突 |
| 存档/清单丢失后 | 仍被识别（靠航线名兜底） | 完全不认 |

怎么选：

- **一只船 / 只想让它稳定搬货** → 用方式 B，最干净，没有航线 AI 抢船。
- **船多、想按区域或远近分组** → 用方式 A，但每条航线只留一个待命站点。

> 两种可以混用。混用时注意 `Shift+I`：它清空整份清单，但**航线上的船会在下一轮
> 自动被重新纳管**（毕竟还在航线里），而手动接管的船不会回来 —— 这也是唯一一个
> 「航线方式比手动方式更省事」的场景。

## 5. 快捷键

| 按键 | 功能 | 你能看到什么 |
|---|---|---|
| `Shift + P` | 扫描当前区域（有缓存会跳过） | 画面跳动；结束后日志有统计 |
| `Shift + F` | 强制重扫（忽略缓存） | 同上，耗时长 |
| `Shift + O` | 接管当前选中的船 | 船名变成 `TRA_...` |
| `Shift + K` | 状态自检 + 必要时复活调度器 | 船名刷新，日志输出完整诊断 |
| `Shift + U` | 开 / 关自动化 | 前缀 `TRA_` ↔ `TRA-OFF_` |
| `Shift + I` | 释放所有被接管的船 | 船名还原成你原来的名字 |
| `Shift + L` | UI 接口探测（开发者用） | 写 `log\TRAtUI_uiprobe.txt` |

`Ctrl + 同字母` 是备用键。中文输入法占用 `Shift+字母` 时改用它。

## 6. 船名看板怎么读

所有被接管的船显示同一行状态，每 10 秒刷新一次：

```
TRA_运行_4艘_A2B2_面粉63
```

| 片段 | 含义 |
|---|---|
| `TRA_` | 已启用（`TRA-OFF_` = 被 `Shift+U` 关掉了） |
| `运行` | 调度正常 |
| `待扫描` | 区域网格为空，按 `Shift+P` |
| `已停止` | 调度协程不在了，按 `Shift+K` 尝试复活 |
| `卡住` | 协程还在但 90 秒无心跳，多半卡在某艘船上 |
| `已关闭` | 按过 `Shift+U` |
| `启动中` | 刚进档，还没跑完第一轮 |
| `4艘` | 已接管的船数 |
| `A2B2` | 舰队分布（只在使用 `TRA_OW_A` / `_B` 时出现） |
| `面粉63` | 当前最大缺口；`平衡` = 没有达到门槛的缺口 |

完整需求清单（每种货缺多少、缺在哪座岛）另写一份纯文本，Alt-Tab 出来就能看：

```
C:\Users\<用户名>\Documents\Anno 1800\log\TRAtUI_status.txt
```

## 7. 它按什么规则搬货

### 两套门槛

| 货物类型 | 最小发运量 | 判定方式 |
|---|---|---|
| **生活必需品**（居民真的在消耗的） | **10** | 双水位：低于容量 60% 就补货；高于 30% 的部分才可以外运 |
| 其它（工业原料、建材） | **50** | 与目标量的差值（原版行为） |

原来所有环节都用硬编码 50，结果是「一座岛饿着、另一座岛还剩 30 吨」，调度器判定「没有可供」，船一动不动。这就是这个分支改它的原因。

### 必需品按「每座岛」判定

不是全区一把抓。只有该岛**真的住着会消耗这种货的人口等级**，它才算必需品：

- 农业岛不会把小提琴、蒸汽马车当必需品。
- 纯生产岛没有居民数据时，退回全区并集兜底（宁可多运，不会少运）。

启动后 `base.log` 里会打一段可以逐项对照的清单：

```
[TRAtUI] 岛 沟中死水岛(id=8451)：必需品 18 种 —— Beef, Beer, Bread, Clay Pipes, Fish, ...
```

### 实时需求：没厂就不运原料

居民需求表会把**加工链原料**也列进去（农民的列表里出现 Flour）。可原料没人加工就是废料。

所以：**凡是本区域自有工厂消耗的原料，都从居民需求里摘掉，改由「岛上有没有那座厂」决定。**

| 岛上的情况 | 结果 |
|---|---|
| 没有面包厂 | 不要面粉 |
| 建了面包厂 | 立刻要面粉 |
| 没有捕鱼厂、有农民 | 照常运鱼（鱼是终端消费品，不是原料） |

`Bar: X` / `Restaurant: X` / `Chemical Plant: Shampoo` 这类**消费场所**不算加工厂，否则酒吧会把杜松子酒从需求里摘掉，导致该运的不运。

### 空区域自动跳过

没开的新世界、没解锁的区域不会每 2 秒刷一次「等待扫描」，而是静默停泊，等你切进去再自动接上。

## 8. 为什么不搬运（排查表）

**先按 `Shift + K`**，它会一次讲清楚卡在哪一步。然后对号入座：

| 看到的现象 | 真正原因 | 怎么办 |
|---|---|---|
| 船名完全没变 | mod 没启用 / 路径放错 | 模块窗口打勾；确认在 `Documents\Anno 1800\mods\` |
| 船名 `待扫描` | 区域网格是空的 | `Shift + P` |
| 船名 `已停止` | 调度协程掉了 | 按 `Shift + K` 会自动尝试复活；不行就重启游戏 |
| 船名 `卡住` | 90 秒没心跳，通常卡在某艘船上 | 等 1～2 分钟，或 `Shift+I` 释放后重新接管 |
| `注意 有 N 艘船在空舱移动` | **航线 AI 抢走了船** | 航线只留一个待命站点，或暂停该航线 |
| 缺口全是「没有任何岛屿可供」 | **两座岛都没有这种货** | 不是调度问题：开岛或补产能 |
| 缺口是 0，船也不动 | 当前真的没有达到门槛的缺口 | 正常。`平衡` 就代表没活干 |
| 按 `Shift+O` 提示「无法识别选中的对象」 | 没点中船体 | 点船本身，别框选、别点船列表图标 |
| 按快捷键毫无反应 | 输入法占了 `Shift+字母` | 改用 `Ctrl + 同字母` |

**最容易误判的是第 6 条**：调度器已经把能搬的都搬完了，剩下的缺口在全区确实找不到货源，加船也不会动。这不是 bug。

## 9. 文件与日志位置

mod 目录：

```
C:\Users\<用户名>\Documents\Anno 1800\mods\TradeRoutesAutomation_OneKey\
```

日志与状态（都在游戏文档目录下）：

| 文件 | 内容 |
|---|---|
| `log\TrRAt_<玩家名>_base.log` | 启动、区域、自检、航线提示 |
| `log\TrRAt_<玩家名>_trade-execute-iteration.log` | 每轮的缺口、供需表、派单结果（**排查主力**） |
| `log\TrRAt_<玩家名>_trades.log` | 每笔订单的执行流水（装了多少、卸了多少） |
| `log\TRAtUI_status.txt` | 当前看板 + 完整需求清单 |
| `log\TRAtUI_takeover.json` | 接管清单（读档后靠它记住哪些船归你） |
| `log\TRAtUI_probe.txt` | 热键送达记录 |

**没有屏幕弹窗**：这个游戏没有任何 Lua 接口能往屏幕上写字（实测 5 条候选全部失败），所以船名是唯一的实时反馈通道，其余全部落日志。

## 10. 参数调优

想改松紧不用改逻辑，只改 `data/trat_fork/mod_trade_planner_ll.lua` 顶部的 `Policy`：

```lua
TradePlannerLL.Policy = {
    minTransferNormal = 50,        -- 非必需品最小发运量
    minTransferBasic  = 10,        -- 必需品最小发运量（调小=更积极，改 50=退回原版）
    basicTargetRatio  = 0.6,       -- 低于容量的这个比例就补货
    basicKeepRatio    = 0.3,       -- 高于这个比例的部分才会外运
    basicNeedEnabled  = true,      -- false = 全部按 50 处理
    basicNeedScope    = "island",  -- "island"=按岛实际人口 | "region"=全区并集（更激进）
    realtimeDemand    = true,      -- false = 退回"居民需求表里有什么就运什么"
    extraBasicGoods   = {},        -- 手工追加算作必需品的 GUID，如 {120008}
};
```

改完必须**完全退出游戏**再进。

## 11. 常见问题

**会不会改我的船名？**
会。船名是唯一能实时显示状态的通道。按 `Shift+I` 释放时会还原成你原来的名字；接管清单里存着原名。

**读档后还要重新接管吗？**
不用。清单写在 `log\TRAtUI_takeover.json`，但**扫描缓存也要在**，否则状态会停在 `待扫描`。

**一艘船能同时被两个区域用吗？**
不能。每条区域循环只管自己区域内的船。

**跨区域（旧世界↔新世界）会运吗？**
不会。原版就是单区域设计，跨区域请用游戏自带航线。

**能多人联机吗？**
不要用。原版就只支持单人，脚本在多人下可能每个客户端各跑一遍。

**画面一直跳是坏了吗？**
不是。扫描阶段镜头要在采样点之间瞬移，这是引擎限制，扫描完就停。

**mod 会不会动我的仓库库存？**
会。它是直接改岛屿库存来「装货/卸货」的，这正是它能工作的方式。运力上限受船的货舱格数限制。

**船名太长挡住别的信息怎么办？**
在任意 Lua 环境里设 `_G["trat_fork_name_tag"] = false` 可关掉船名看板，状态只写 `TRAtUI_status.txt`。
